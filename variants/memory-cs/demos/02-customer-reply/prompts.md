# 데모 2 — 고객 회신 메일 자동화 프롬프트 스크립트

> 강사 시연용. 진행 시간: 11분 (29:00~40:00)
> **주의**: 본 시연은 가상 데이터만 사용. 청중에게 실 고객명·실 데이터 입력 금지 재강조.

---

## 입력 파일 (시연 폴더에 준비)

- `customer_email.txt` — 고객 escalation 메일 (가상)
- `fa_summary.md` — 사내 FA 요약 (데모 1 산출물 활용)
- `customer_x_tone.md` — Customer X 톤 매뉴얼

## 프롬프트 1 — 분석 단계

> 이 폴더의 파일 3개를 읽어줘:
> 1. customer_email.txt — 고객이 보낸 메일
> 2. fa_summary.md — 우리 사내 FA 요약
> 3. customer_x_tone.md — Customer X 톤 매뉴얼
>
> 고객이 요구한 4가지에 대해 우리가 답할 수 있는 내용을
> 표로 정리해줘. 답할 수 없는 건 "사내 확인 필요" 표시.
> 표: 고객 질문 / 답변 가능? / 답변 내용 또는 사유

### 예상 출력

| 고객 질문 | 답변 가능? | 답변 내용 또는 사유 |
|---|---|---|
| 1. Root cause | 부분 | "조사 중, ECC 한계 추정"까지만 |
| 2. Affected lots | 부분 | K42 확인, 인접 lot 5/20 결과 후 |
| 3. Replacement/RMA | **사내 확인 필요** | 5/27 회의 결정 사항 |
| 4. Long-term fix | 가능 | ECC v2, 6/1 fab 출하분부터 |

---

## 프롬프트 2 — 작성 단계

> 위 분석을 바탕으로 영문 회신 메일 reply.md 작성해줘.
>
> 원칙:
> - customer_x_tone.md 매뉴얼 엄격히 준수
> - spec 수치 정확히 인용 (1e-8 max)
> - 추측 표현 절대 금지 (might/probably/could be 등)
> - 미확정 사항은 "we are currently investigating" / "to be confirmed by [date]"
> - 우리 입장 회피 표현 금지
> - 길이: 250~350 단어 목표
> - 4섹션 구조 (고객 질문 1~4 대응)
> - 마지막에 "Next steps from our side" 일정 정리
>
> 한글 요약도 reply_summary_kr.md로 따로 만들어줘:
> - 회신 요점 4가지
> - 우리가 약속한 다음 액션 일정 표
> - 발송 전 체크리스트
> - 사내 후속 일정 (5/14, 5/20, 5/25, 5/27)

### 예상 출력
- `reply.md`: 영문 회신, 250~300 단어, 4섹션 + Next steps
- `reply_summary_kr.md`: 한글 요약, 표·체크리스트 포함

## 시연 흐름 (11분)

### 0:00~2:00 — 상황 + 입력 3종 보여주기
- "데모 1의 회의록이 우리 손에 있는 상황"
- 입력 3개 파일 차례로 열기:
  - `customer_email.txt` — "고객사 X가 보낸 escalation, 영문"
  - `fa_summary.md` — "데모 1 회의록의 사내용 요약"
  - `customer_x_tone.md` — "Customer X 톤 매뉴얼 (사내 자료)"
- 강조: "이 3가지를 합쳐서 회신 만드는 게 핵심"

### 2:00~4:00 — 프롬프트 1 (분석)
- 강사가 입력
- Claude의 표 출력 보기
- "답변 가능 / 사내 확인 필요"가 명확히 분리되는 게 핵심
- "이게 톤 매뉴얼의 가치 — 무엇을 말해도 되는지부터 정리"

### 4:00~7:00 — 프롬프트 2 (작성)
- 강사가 입력
- 강조: **"추측 표현 절대 금지"** — 가드레일 명시의 중요성
- 결과 2개 파일 생성 (영문 + 한글 요약)

### 7:00~9:00 — 결과 검토
- `reply.md` 열어보기
  - 4섹션 구조 확인
  - "might/probably" 단어 검색 → 없음 확인
  - spec 수치 (1e-8) 정확한지 확인
- `reply_summary_kr.md` 열어보기
  - 한글 요약 표
  - 발송 전 체크리스트

### 9:00~11:00 — 메시지 + 한계
- **메시지**: "매일 5통 회신 = 매일 1시간 절감"
- **한계 강조 (중요)**:
  - **절대 검토 없이 발송 금지**
  - Spec 수치는 매번 datasheet 원본 대조
  - 톤 매뉴얼이 부실하면 결과도 부실
  - 실 고객·실 lot 데이터 입력 금지 (가상 데이터만)
  - 시니어 검토 필수

## 트러블슈팅

| 증상 | 대응 |
|---|---|
| 추측 표현이 끼어듦 | 프롬프트에 "might/probably 단어 절대 금지" 추가 강조 |
| 영문이 너무 formal/딱딱함 | tone 매뉴얼에 "Dear 금지, Hi 권장" 같은 구체 가이드 |
| Spec 수치 틀림 | 프롬프트에 "1e-8 max 정확히 인용" 직접 박기 |
| 길이가 너무 김 | "250~350 단어" 명시, "단락 3~4문장 max" 추가 |
| 사내 미공개 정보 노출 우려 | fa_summary.md에 "공유 OK" 항목만 두기 |
