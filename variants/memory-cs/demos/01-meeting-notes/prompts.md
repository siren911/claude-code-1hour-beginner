# 데모 1 — FA 회의록 정리 프롬프트 스크립트

> 강사 시연용. 진행 시간: 11분 (18:00~29:00)
> **주의**: 본 시연은 가상 데이터만 사용. 청중에게 "실 lot 정보 절대 입력 금지" 강조.

---

## 메인 프롬프트

> 이 폴더의 before.txt는 FA 회의 메모야.
> after.md로 정리해줘. 구조:
> 1. 회의 정보 (일시·장소·참석·주제)
> 2. 핵심 이슈 (lot·spec·BER 현황을 표로)
> 3. FA 분석 결과
> 4. 결정사항 (표)
> 5. 액션 아이템 (담당·작업·기한 표)
> 6. 고객사 X 1차 회신 포함 항목 (체크리스트)
> 7. 다음 회의
>
> 고객 영향 ranges와 lot ID는 명시. spec 수치 정확히 인용.
> 한국어로 작성. 추측·과장 표현 금지.

---

## 예상 Claude 행동

1. `Read("before.txt")` — 메모 읽기
2. 구조 분석·도메인 용어 식별 (lot/BER/ECC/WL/wafer)
3. `Write("after.md")` — 정리된 회의록 저장
4. 결과 요약 출력

---

## 시연 흐름 (11분)

### 0:00~2:00 — 상황 + 입력 보여주기
- "오늘 오후 FA 회의 끝나고 메모만 남은 상황"
- `before.txt` 텍스트 에디터로 열어서 청중에게 보여주기
- 용어 짚기: lot, BER, ECC, WL — 청중이 도메인 친숙하니 빠르게
- 강조: "이거 그대로 슬랙에 올리면 못 읽어요. 정리가 필요"

### 2:00~5:00 — 강사 시연
- 터미널에서 `claude` 실행
- 메인 프롬프트 입력
- Claude의 도구 호출 과정 보여주기 (Read → Write)

### 5:00~7:00 — 결과 검토
- `after.md` 열어서 표 구조 확인
- "어, BER 수치 정확하네"
- "기한 자동 추출됐네 (5/15, 5/20, 5/25, 5/14, 6/1)"
- 표가 마크다운 그대로 슬랙에 붙여넣기 가능함을 시연

### 7:00~9:00 — 변형 프롬프트 1개
> 이 회의록 기반으로 고객사 X 1차 회신 메일 골격도 잡아줘.
> reply_skeleton.md로 저장. 영문, formal 톤.
> 단, 실제 회신은 데모 2에서 본격 다룰 예정이라 골격만.

- 예상 출력: 4섹션 영문 골격 (Cause / Affected lots / Temporary action / Long-term)
- "이 골격이 다음 데모 입력이 됩니다 — 자연스럽게 연결되죠"

### 9:00~11:00 — 메시지 + 한계
- **메시지**: "FA 회의록 정리 매주 1시간 → 5분"
- **한계 강조 (중요)**:
  - 사람이 반드시 검토 — 특히 lot ID·spec 수치
  - AI가 결정사항을 임의로 추가하지 않았는지 확인
  - 고객명·실 lot 정보는 절대 입력 금지 (가상 데이터만)
