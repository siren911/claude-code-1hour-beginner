## 1. 배경 (Why)

### 1-1. 직군 특수성 (메모리 반도체 회사 CS팀 대상)
메모리 반도체 회사 CS(Customer Support)팀원은 다음 업무에 매일 시간을 씀:
- 고객사 escalation 메일 처리 (영문 다수)
- FA(Failure Analysis) 결과 공유 회의록 작성
- Defect log·BER 데이터 분석 → 고객 회신 메일 작성
- 고객별 VOC(Voice Of Customer) 추적 → 패턴화
- Datasheet 인용 기반 공식 답변 작성

이 업무 대부분은 **"엑셀 + 메일 + Word"** 조합으로 수동 처리되어 시간 소모가 큼.

### 1-2. AI 도구 활용 기회
- 정형화된 작업이 많아 AI 자동화 효과가 큼
- 단, **NDA·고객 데이터 민감도가 매우 높음** → 외부 AI 사용에 제약
- 회사 차원의 Claude Code 도입이 승인된 경우, "어떻게 안전하게 활용할지" 가이드 필요

### 1-3. 비전
> "메모리 반도체 회사 CS팀원이 1시간 후 자기 사내 PC에서<br/>
> FA 회의록·고객 회신·VOC 분석 작업을 AI에게 위임할 수 있다.<br/>
> 단, 사내 보안 정책을 엄격히 지키면서."

### 1-4. 사용 컨텍스트 — 사내 교육 자료
- **이 자료는 메모리 반도체 회사 CS팀 사내 교육 템플릿**입니다. fork 후 자기 회사 브랜드·가이드라인에 맞게 수정해 사용.
- 외부 fork·재사용을 위해 페르소나·예시는 가공된 가상 데이터 사용.

### 1-4. 전제 (이번 자료의 가정)
- ✅ 회사가 Claude Code 사용을 **공식 승인**한 상태
- ✅ 사내 IT/보안팀이 사용 범위와 가이드라인을 배포함
- ✅ 엔터프라이즈 계약 또는 API 학습 미사용 옵션 적용
- ❓ 청중은 도메인 용어(BER·retention·ECC·lot·die 등)에 익숙

## 2. 대상 청중 (Who)

### 2-1. Primary Persona — "박과장"
- 30대 후반, 메모리 반도체 회사 CS팀 5년차
- 매일 평균 30통 고객 메일 처리 (50% 영문)
- Excel pivot·VLOOKUP 능숙, 파이썬은 모름
- 매주 FA 회의 1~2회, 회의록 작성 본인 몫
- ChatGPT는 가끔 쓰지만 "회사 자료는 못 넣으니 효과 제한적"이라 느낌

### 2-2. Secondary Persona — "이주임"
- 20대 후반, 입사 2년차
- 선배가 시키는 보고서·메일 초안 작성에 시간 많이 씀
- 영문 메일 작성 부담 큼 (번역기 의존)
- AI 도구에 호기심 큼, "잘 쓰면 야근 줄겠는데?"

### 2-3. 비대상
- R&D·제품 개발 엔지니어 → 원본(상급자용 jhl-labs/claude-code-1hour)
- 본사 마케팅·세일즈팀 → 일반 직장인용 자료
- 고객 직접 대면 영업팀 → 별도 자료 필요

## 4. 데모 구성 (What — 4종)

### 4-1. 메인 데모 (각 11분)

#### 데모 1: 회의록 요약
- **상황**: FA 결과 공유 회의 메모 (lot 정보·BER·고객 영향 포함)
- **입력**: 비정형 텍스트 메모 (`before.txt`)
- **출력**: 결정사항·액션 아이템·고객 영향 표가 포함된 markdown (`after.md`)
- **메시지**: FA 회의록 자동화 = 매주 1시간 절감

#### 데모 2: 고객 회신 메일 자동화
- **상황**: 고객 escalation 메일 + 내부 FA 결과 자료
- **입력**: 영문 고객 메일 + FA 요약 데이터
- **출력**: 영문 회신 메일 초안 + 사내 공유용 한글 요약
- **원칙 명시**: spec 인용·추측 금지·고객별 톤 매뉴얼 참조
- **메시지**: 매일 5통 회신 = 매일 1시간 절감

### 4-2. 미리보기 데모 (각 2분)

#### 데모 3: 고객 불량 지수 대쉬보드 (예고)
- **상황**: 분기별 고객사별 defect 인덱스 추세
- **시연 범위**: "이런 명령 한 줄로 표 + 차트가 생성됩니다" 1분 + 결과 보여주기 1분
- **메시지**: 본격 자동화는 Day 2 "나만의 Agent" 세션에서

#### 데모 4: 고객 성향 VOC 대쉬보드 (예고)
- **상황**: 고객별 메일 수십 통에서 반복되는 키워드·톤·요구 패턴
- **시연 범위**: 6개월 VOC 텍스트 모음 → 고객별 성향 카드 1장 자동 생성
- **메시지**: "이 고객은 보통 spec 인용을 좋아함" 같은 인사이트 자동화

### 4-3. 데모별 시간 배분 (총 26분)

| 데모 | 시간 | 깊이 |
|---|---|---|
| 1. 회의록 | 11분 | Deep (프롬프트·결과·변형) |
| 2. 메일 | 11분 | Deep (2단계·검증) |
| 3. 불량 대쉬보드 | 2분 | Preview (결과 보여주기) |
| 4. VOC 대쉬보드 | 2분 | Preview (결과 보여주기) |

## 7. 제약사항 (Constraints)

### 7-1. 보안 (가장 중요)
- 데모 데이터는 **모두 가상** — 실 고객명·lot ID·BER 수치 절대 사용 금지
- 사내 IT/보안팀 가이드 우선 — 본 자료는 보조
- 청중이 자기 업무에 적용 시 "어디까지 OK인지" 명시 슬라이드 1장 별도

### 7-2. 시간
- 본 세미나: 60분 + Q&A 10분
- 준비 기간: 7~10일 (1인 작업)

### 7-3. 기술
- 사내 PC 환경 (Windows 우선, macOS도 일부)
- Node.js 설치 권한 = 사내 IT 사전 협의 필요
- 인터넷 접근 = Anthropic API 도메인 사내 방화벽 허용 여부 확인

### 7-4. 라이선스·비용
- Anthropic 엔터프라이즈 계약 가정 (학습 미사용 + 감사 로그)
- 비용: 사내 청구 코드 안내 (실제 청구는 사내 절차)
