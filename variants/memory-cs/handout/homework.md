## ⚠️ 시작 전 — 사내 가이드 확인

오늘 끝나고 30분 안에 작업을 하기 전에:

1. **사내 IT/보안팀 가이드 확인**
   - Claude Code 사용이 우리 부서·내 직무에서 허용되는가?
   - 어떤 데이터까지 입력 가능한가?
   - 청구 코드는 있는가?
2. **사내 PC 설치 권한 확인**
   - Node.js 설치 권한 보유? (없으면 IT 요청)
3. **본 자료의 모든 시연은 가상 데이터** — 실 데이터 입력 금지

## 오늘 끝나고 30분 (필수)

### Step 1 — 설치 (5분)

```powershell
node -v                                # 18+ 확인
npm install -g @anthropic-ai/claude-code
claude login
```

> 사내 프록시 사용 시 npm config 별도 설정 필요. IT 가이드 참조.

### Step 2 — 첫 실행 (5분)

```powershell
mkdir ~/cs-test
cd ~/cs-test
claude
```

첫 프롬프트:
> 이 폴더에 hello.md 파일 만들어줘.
> 메모리 CS팀 신입 환영 메시지 한 줄, 이모지 1개 포함.

→ 폴더에 `hello.md` 생겼는지 확인.

### Step 3 — CS 직무 첫 작업 1개 (20분)

자기 일에서 "정리해야 하는 귀찮은 거" 1개 선택 (**가상 데이터로**):

| 직무 | 추천 작업 |
|---|---|
| 회의록 작성 자주 함 | 가상 FA 회의 메모 → 회의록 markdown |
| 영문 회신 많음 | 가상 고객 메일 → 회신 초안 + 한글 요약 |
| 데이터 정리 | 가상 BER CSV → 고객사별 표 |
| VOC 정리 | 가상 메일 3통 → 고객 성향 카드 |

→ `claude`로 시켜보고 결과 확인.

## 내일까지 (10분)

### CLAUDE.md 만들기

`~/cs-test` 폴더에 `CLAUDE.md`:

```markdown
# 내 작업 환경 (메모리 CS)

- 직무: [메모리 CS, N년차]
- 자주 만드는 결과물: [FA 회의록 / 고객 회신 / VOC]
- 톤: formal, spec 인용 정확, 추측 금지
- 한글 요약 별도 파일로 항상 생성
- 도메인 용어: BER·lot·WL·ECC·DDR5·LPDDR5 등 영문 원문 유지
- [당신만의 규칙 — 예: "이모지는 공식 메일에 쓰지 않기"]
```

### 다시 한 번 시켜보기

`CLAUDE.md`가 있는 폴더에서 어제 시킨 작업 다시 시켜보고 결과 비교.
- 톤이 일관되게 적용됐는지?
- 한글 요약이 자동으로 따라오는지?

## 1주일 안 (1~2시간)

### 동료 1명에게 시연 (5분)

- 옆자리 CS 동료에게 시연
- 같이 따라하게 하기
- 누군가에게 설명하면서 본인이 더 잘 알게 됨

### 팀 공통 CLAUDE.md 초안

- 우리 CS팀이 자주 쓰는 양식 적기
- 우리 팀 금지 사항 (예: "실 고객명 절대 입력 금지")
- 사내 위키 / 팀 슬랙 채널에 공유

### 고객별 톤 매뉴얼 1개 작성 (선택)

- 자주 응대하는 고객 1사 선택
- `customer_tone/[고객명].md` 형식으로 톤 매뉴얼 작성
- 다음 회신 작성 시 활용
