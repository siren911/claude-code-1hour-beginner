### §1 — Claude Code란? (5분 · 00:00~05:00)

**목표**: ChatGPT 사용자에게 "이건 뭐가 다른지" 명확히

**구성**:
1. (1분) 1줄 정의
   > "내 컴퓨터의 파일을 직접 읽고 고쳐주는 AI 동료"
2. (2분) 비교 표
   | | ChatGPT | Claude Code |
   |---|---|---|
   | 어디서 답함 | 웹 브라우저 | 내 노트북 터미널 |
   | 파일을 보나? | 못 봄 (복붙해야) | 직접 읽음 |
   | 파일을 고치나? | 못 고침 (복붙해야) | 직접 고침 |
   | 명령 실행? | 못함 | 함 (빌드·테스트·git) |
3. (2분) 한 줄 데모 미리보기 (영상 30초)
   - "이 폴더 정리해줘" → 실제로 정리되는 화면

**핵심 메시지**: "복붙이 아니라 위임"

**슬라이드 수**: 4장

### §2 — 첫 시도 라이브 (15분 · 05:00~20:00)

**목표**: 청중이 보는 앞에서 강사가 첫 작업 1개 완료. 끝나면 "나도 할 수 있겠다" 확신.

**시나리오**:

| 시간 | 강사 행동 | 청중 액션 (선택) |
|---|---|---|
| 05:00~06:00 | 빈 폴더 만들고 `claude` 실행 | 같이 따라할 사람만 |
| 06:00~08:00 | 첫 프롬프트: "이 폴더에 내 자기소개 markdown 파일 만들어줘. 이름은 OOO, 직업은 OOO" | 화면 보기 |
| 08:00~10:00 | Claude가 about.md 만드는 과정 보기 | "어, 진짜 만드네?" |
| 10:00~12:00 | "이모지도 넣고, 좋아하는 것 섹션도 추가해줘" | 대화의 흐름 체득 |
| 12:00~14:00 | "근데 직업은 PM이 아니라 디자이너로 바꿔줘" | 수정도 대화로 |
| 14:00~15:00 | 완성된 파일 텍스트 에디터로 열어보기 | "와, 진짜 파일 있네" |
| 15:00~17:00 | 깨알 팁: Tab으로 자동완성·`/clear`로 새 대화·`exit`로 종료 | |
| 17:00~20:00 | 같이 따라하고 싶은 사람을 위한 멈춤 시간 (옆 사람 도와주기) | 페어링 활성화 |

**핵심 메시지**: "코딩이 아니라 대화입니다"

**라이브 데모 백업**: 인터넷 끊김 대비 90초 녹화 영상 1개

**슬라이드 수**: 8장 (프롬프트·결과 화면 위주)

### §3 — 라이브 데모 2종 (25분 · 20:00~45:00)

#### 데모 1: 회의록 정리 (12분 · 20:00~32:00)

**상황 설정**: "방금 1시간 회의 끝나고 메모만 남은 상태"

**입력 파일** (`demos/01-meeting-notes/before.txt`):
```
2026-05-13 화 PM 2시 분기 기획 회의
참석: 김지원, 박민준, 이수아
- 신규 기능 우선순위 논의함
- 지원: 검색 개선이 1번 (CS 인입 30% 차지)
- 민준: 결제 모듈 리팩토링도 시급 (장애 2건 발생)
- 수아: 일단 검색 먼저, 결제는 다음 분기
- 결정: 검색 개선 5월말까지, 결제는 6월
- 액션: 지원 - 검색 PRD 5/20까지, 민준 - 결제 후속 분석
- 다음 회의: 5/27 같은 시간
```

**프롬프트**:
> "이 텍스트는 회의 메모야. 깔끔한 회의록 markdown으로 정리해줘. 결정사항, 액션 아이템(담당자·기한 포함), 다음 회의 섹션으로 나눠줘"

**예상 출력** (`after.md`):
```markdown
# 분기 기획 회의
- **일시**: 2026-05-13 (화) 14:00
- **참석**: 김지원, 박민준, 이수아

## 결정사항
- 검색 개선 우선 (5월말 완료)
- 결제 모듈 리팩토링 보류 → 6월 일정

## 액션 아이템
| 담당 | 작업 | 기한 |
|---|---|---|
| 김지원 | 검색 PRD 작성 | 2026-05-20 |
| 박민준 | 결제 모듈 후속 분석 | - |

## 다음 회의
- 2026-05-27 (화) 14:00
```

**시연 흐름** (12분):
- 0~2분: 상황 설명·입력 파일 보여주기
- 2~5분: 강사가 프롬프트 입력·Claude 출력 보기
- 5~8분: 출력 결과 보고 "어 표도 만들어줬네" "기한도 알아챘네"
- 8~10분: 변형 프롬프트 1개 — "5월 27일 회의 안건도 추측해서 3가지 적어줘"
- 10~12분: "이건 ChatGPT로도 되지 않나?" 솔직 답변 → 파일을 직접 만들어준다는 차이

**핵심 메시지**: "한 시간 걸리던 작업이 1분, 게다가 형식까지 맞춰서"

---

#### 데모 2: 데이터 정리 (13분 · 32:00~45:00)

**상황 설정**: "엑셀로 모은 명단인데 엉망. 이메일 오타, 중복, 빈칸 다 있음"

**입력 파일** (`demos/02-data-cleanup/messy.csv`):
```csv
name,email,amount
홍길동,hong@example.com,15000
김철수, kimcs @example.com ,
이영희,younghee@exampl.com,25000
홍길동,hong@example.com,15000
박민수,minsoo@example,33000
,empty@example.com,12000
정수아,sua@example.com,abc
```

**프롬프트 1**:
> "이 CSV 파일의 문제점을 찾아서 표로 정리해줘. 어떤 줄에 무슨 문제 있는지"

**예상 출력**:
| 줄 | 문제 | 비고 |
|---|---|---|
| 2 | 이메일 공백, amount 빈칸 | 'kimcs @example.com' |
| 3 | 도메인 오타 | exampl.com → example.com 추정 |
| 4 | 중복 (홍길동 동일 행) | 1행과 같음 |
| 5 | 이메일 형식 오류 | TLD 없음 |
| 6 | name 빈칸 | |
| 7 | amount 숫자 아님 | 'abc' |

**프롬프트 2**:
> "위 문제 다 고쳐서 clean.csv 만들어줘. 고친 내역은 changes.md에 적어줘"

**시연 흐름** (13분):
- 0~2분: 상황·입력 파일 보여주기
- 2~5분: 프롬프트 1 → 분석 결과
- 5~9분: 프롬프트 2 → clean.csv + changes.md 생성
- 9~11분: 결과 검증 (열어서 확인)
- 11~13분: "데이터 손실 위험" — 정말 중복이 맞을까? → AI 검증의 중요성 강조

**핵심 메시지**: "엑셀 1시간 → AI 1분. 단, 결과 검증은 사람의 몫"

### §4 — 누가 가장 좋아질까 (5분 · 45:00~50:00)

**구성**:
1. (2분) 역할별 활용 예시 3가지
   - **PM·기획자**: 회의록·요구사항·이메일 정리
   - **학생·신입**: 과제·정리노트·자기소개서
   - **부트캠프 수강생**: 막힐 때 옆에 멘토 (오답도 빨리 알아챔)
2. (2분) 솔직한 한계
   - AI는 가끔 그럴듯한 거짓말 (환각)
   - 중요한 결정은 사람이
   - 회사 보안은 별도 검토
3. (1분) "검토 시작점"을 0%에서 70%로

**슬라이드 수**: 3장

### §5 — 시작하기 + 내일까지 (10분 · 50:00~60:00)

**구성**:

#### 5-1. 오늘 끝나고 30분 (3분 설명)
1. 설치 (5분)
   ```
   # macOS / Linux
   npm install -g @anthropic-ai/claude-code
   claude login

   # Windows (PowerShell)
   npm install -g @anthropic-ai/claude-code
   claude login
   ```
2. 빈 폴더에서 `claude` 입력 (1분)
3. 자기 일에서 가장 귀찮은 텍스트 작업 1개 시켜보기 (24분)

#### 5-2. 내일까지 (2분 설명)
- 폴더 안에 `CLAUDE.md` 파일 5줄 만들기 (예시 보여줌)
  ```markdown
  # 내 작업 환경
  - 직업: PM
  - 자주 쓰는 양식: 회의록, 주간 리포트
  - 좋아하는 톤: 간결, 표 사용
  - 한국어로 답변
  - 결정사항·액션 항상 분리
  ```
- 자주 쓰는 명령 1개 시켜보기

#### 5-3. 1주일 차 (2분 설명)
- 친한 동료에게 시연하기
- 우리 팀에 맞는 CLAUDE.md 만들기

#### 5-4. 자주 막히는 곳 (3분)
| 증상 | 해결 |
|---|---|
| `claude` 입력해도 안 됨 | Node.js 설치 확인 (`node -v`) |
| 답이 영어로 옴 | "한국어로 답해줘" CLAUDE.md에 |
| 회사 자료 넣어도 돼? | 엔터프라이즈 옵션 안내, 일단 가상 데이터로 |
| 인터넷 끊김 | Claude는 인터넷 필요, 로컬 캐싱 안 됨 |

**슬라이드 수**: 6장

### Q&A (10분 · 60:00~70:00)

**선별 6질문** (강사가 다 준비, 실제로는 청중 질문 우선):

1. **돈 들어요?** — 첫 사용은 무료 한도 안에서 가능, 본격 사용은 월 USD 단위
2. **ChatGPT가 더 싸지 않아요?** — 파일 직접 수정 가능 여부가 결정적 차이
3. **회사 자료 보안은요?** — 엔터프라이즈는 학습 미사용, NDA 코드는 사내 정책 확인 후
4. **AI가 잘못된 답 주면 어떻게 알아요?** — 결과는 항상 검토, 중요한 거는 백업 후 시도
5. **코드 한 줄도 모르는데 진짜 쓸 수 있어요?** — 데모 1·2가 바로 그 답
6. **다음에 배울 건요?** — CLAUDE.md 고도화 → Skill → MCP 순서 (참고: 원본 자료 jhl-labs)

## 3. 기술 스택 — 슬라이드 도구 선택

### 3-1. 후보 비교

| 도구 | 작성법 | 장점 | 단점 |
|---|---|---|---|
| **Slidev** | Markdown + Vue | 마크다운 친화, 코드블록·트랜지션 강력, GitHub Pages 쉬움 | Node 빌드 필요 |
| Reveal.js | HTML/JS | 자유도 100%, 원본과 동일 | 작성·유지 비용 큼 |
| marp | Markdown | 가장 단순, VS Code 플러그인 | 디자인 변형 제약 |
| Astro Starlight | Markdown + Astro | 문서 사이트 + 슬라이드 모드, 검색·사이드바 좋음 | 구조 복잡 |

### 3-2. 선택: **Slidev**
**이유**:
- 자료 자체가 "AI 친화적" — 마크다운이라 청중도 fork해서 자기 회사용으로 수정 쉬움 (메타 가치)
- GitHub Pages 자동 배포 공식 가이드 존재
- 코드 하이라이팅·라이브 코딩 모드 강력
- 한국어 폰트 지원 양호

**대안 (B안)**: marp — 일정 빠듯하거나 디자인 시간 부족하면 전환

## 5. CI/CD — 배포 흐름

```

  ↓

  ↓
```

## 6. 콘텐츠 디자인 원칙

### 6-1. 슬라이드 디자인
- 글자 크기 큼 (뒷자리 보임)
- 한 슬라이드 = 한 메시지 (다중 메시지 금지)
- 코드는 항상 비교 형태 (Before/After)
- 이미지·이모지 적극 사용 (긴장 완화)

### 6-2. 어휘 선택
| ❌ 금지 어휘 | ✅ 권장 어휘 |
|---|---|
| 에이전틱 루프 | 알아서 일하는 흐름 |
| 컨텍스트 | 맥락 |
| 프로그매틱 | 자동으로 |
| 토큰 | 분량 단위 |
| Subagent | (이번 자료에 없음) |

### 6-3. 청중 모드 전환
- 강의 모드: 슬라이드 보기
- 데모 모드: 터미널 화면 + 큰 글씨
- 실습 모드: "지금 같이 따라하실 분?" + 도와주기
