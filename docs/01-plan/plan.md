# Plan — Claude Code 1시간 세미나 (초급자용)

> **BKIT PDCA Plan 단계 산출물**
> 원본 참고: [jhl-labs/claude-code-1hour](https://jhl-labs.github.io/claude-code-1hour/) — 메모리 컨트롤러/펌웨어 엔지니어 대상 상급자용
> 작성일: 2026-05-13

---

## 1. 배경 (Why)

### 1-1. 문제 정의
- 원본 자료는 메모리 컨트롤러·U-Boot·NAND 드라이버 엔지니어 대상으로 매우 도메인 특화됨
- 비개발자/입문자 청중에게는 진입 장벽이 너무 높음 (Kconfig·BCH-8 ECC·sandbox 빌드 등)
- 그러나 "AI 동료와 일하기"라는 본질 가치는 누구에게나 유효

### 1-2. 기회
- Claude Code의 핵심 메시지 — "지시 → 자율 실행 → 검토"는 비개발자도 이해 가능
- 초급자 진입 자료가 부족 (대부분 영문·개발자 중심)
- 1시간 세미나 형식은 점심·퇴근 후 인입 자리에 알맞음

### 1-3. 비전
> "코딩을 한 줄도 모르는 사람이 1시간 후 자기 노트북에서 AI에게 일을 시킬 수 있다"

---

## 2. 대상 청중 (Who)

### 2-1. Primary Persona — "지원"
- 30대 PM/기획자, 컴공 비전공
- 매일 회의록·요구사항 문서·CSV 데이터 정리에 시간 씀
- ChatGPT는 매일 쓰지만 "복붙" 단계에 머물러 있음
- 노트북에 터미널을 열어본 적 없음

### 2-2. Secondary Persona — "민준"
- 부트캠프 3개월차 수강생
- HTML/CSS·자바스크립트 기초 수준
- VS Code는 쓰지만 npm·git은 가끔 막힘
- "더 잘 쓰는 법"을 찾는 중

### 2-3. 비대상 (이 자료는 이런 사람에겐 부족함)
- 시니어 개발자 → 원본(상급자용) 추천
- 임베디드·펌웨어 엔지니어 → 원본 추천
- DevOps/MLOps 전문가 → 별도 자료 필요

---

## 3. 학습 목표 (Outcomes)

### 3-1. 1시간 종료 시점 (DoD = Definition of Done)
청중이 다음을 할 수 있어야 함:

| # | 행동 | 검증 방법 |
|---|------|----------|
| 1 | Claude Code가 무엇인지 자기 문장으로 설명 | "ChatGPT와 어떻게 다른가요?" 질문에 30초 답변 |
| 2 | 자기 노트북에 설치 시도 가능 | 슬라이드 OS별 명령어 따라 입력 |
| 3 | 첫 프롬프트 시도 가능 | "내 폴더에 README 만들어줘" 같은 작업 |
| 4 | "맥락 주기" 개념 이해 | 좋은 프롬프트 vs 나쁜 프롬프트 구분 |

### 3-2. 비목표 (이번 1시간에 다루지 않음)
- ❌ MCP 서버 설정
- ❌ Subagent·Hooks·Skills 고급 사용
- ❌ CI/CD 파이프라인 통합
- ❌ 코드 리뷰·리팩토링 (상급자용 영역)
- ❌ 임베디드/펌웨어/시스템 프로그래밍

### 3-3. Stretch Goals (할 수 있으면 좋음)
- CLAUDE.md 파일 5줄 작성 가능
- `/clear` 명령으로 컨텍스트 관리 시도

## 4. 산출물 (What)

### 4-1. 핵심 산출물
1. **GitHub Pages 슬라이드 사이트** (Slidev 기반)
2. **데모 자산 폴더** (before/after 파일 2세트)
3. **핸드아웃** (PDF 1장 — 설치 명령·30분 가이드·자주 막히는 곳)
4. **BKIT 설계 문서** (Plan/Design — 본 문서 포함)

### 4-2. 배포
- GitHub Pages, 자동 배포 (main push → CI)
- Fork 가능한 구조 (다른 강사가 자기 회사용으로 가져다 쓸 수 있게)
- 라이선스: MIT 또는 CC-BY-4.0 (자료 재사용 허용)

---

## 5. 성공 기준 (KPI)

### 5-1. 청중 측정
- **즉시**: 세미나 종료 후 30분 내 50% 이상 첫 실행 성공 (현장 설문)
- **24시간 내**: 30% 이상 자기 작업 1개 시도
- **만족도**: 5점 척도 평균 4.0 이상

### 5-2. 자료 측정
- GitHub Star ≥ 50 (3개월 내, 자료 품질 신호)
- Fork ≥ 10 (재사용 가능성 신호)
- Issue·PR ≥ 5 (커뮤니티 참여 신호)

### 5-3. 운영 측정
- 라이브 데모 성공률 (3회 진행 시 3회 모두 데모 완료)
- 60분 시간 준수율 (±5분 이내)

---

## 6. 제약사항 (Constraints)

### 6-1. 시간
- **본 세미나**: 60분 강의 + 10분 Q&A
- **준비 기간**: 7일 (1인 작업 기준)

### 6-2. 기술
- 청중 노트북 OS 다양 (Windows/macOS/Linux) → 멀티 OS 지원 필수
- Claude Code 설치 = Node.js 필요 → 그 부분도 안내
- 인터넷 필요 (오프라인 불가) → 행사장 Wi-Fi 점검 필요

### 6-3. 비용
- 청중 Claude API 비용 부담 — 첫 사용은 무료/저비용임을 명시
- 강사 시연용 계정은 사전 충전 필요

### 6-4. 보안
- 청중 회사 자료를 데모에 쓰지 않음 (가상 데이터)
- "회사 자료 보안" Q&A는 솔직하게 (엔터프라이즈 옵션 안내)

---

## 7. 가정 (Assumptions)
- 청중은 노트북·인터넷·Wi-Fi 접근 가능
- 청중은 "터미널"이라는 단어를 들어본 적은 있음 (사용은 못함)
- 강사는 Claude Code 6개월 이상 사용 경험
- 행사장은 큰 모니터 + 마이크 제공

## 8. 의존성 (Dependencies)
- Slidev (또는 동급 슬라이드 도구) 라이선스·기능
- GitHub Pages 호스팅 가능 여부
- Anthropic Claude API 가용성 (데모 당일)
